# v3.4.0

Load fully evaluated asynchronous ESM exports through the synchronous factory:

```js
const load = require("esm-sync")(module)
const { client } = load("./client.mjs")
```

## Module loading

- Top-level await, transitive async dependencies, cycles, dynamic imports,
  module-body async iteration, and resource disposal preserve live bindings,
  module identity, and original failure values.
- Import attributes, text/deferred imports, string-named exports, and ambiguous
  star re-exports are handled by the module graph.
- Public `exports`, package-private `imports`, `node:` specifiers, and modern
  `import.meta` helpers are supported. Modules can create their own `require`.
- CommonJS interop preserves constructor identity. Jest 26 registry resets,
  isolation, and VM globals are covered; its inherited outer modules follow
  Jest's own behaviour.

## Installation and compatibility

Published JavaScript works without a local build. Timer/I/O-backed synchronous
awaits need a matching native bridge on the initial CommonJS startup stack.
The bridge targets Node 22+ and is specific to OS, architecture, and Node ABI.
The install hook reuses a bundled bridge or attempts compilation with matching
headers and a C++20 compiler. The runtime never compiles or downloads a bridge.

Without a bridge, ordinary loads and microtask-settled awaits remain available;
synchronous timer/I/O awaits fail explicitly. pnpm users can allow or decline
the build hook through their workspace policy. See
[async module loading](../async-module-loading.md) for exact contexts, timeout,
installation policy, and error codes.

The factory signature, options, exported aliases, physical `esm.js`/`index.js`
paths, and TypeScript declarations remain available. Ordinary loading retains
the declared Node `>=6` engine range; syntax and bridge features have additional
host requirements. Current CI covers Node 22/24/26 on Linux/macOS/Windows.
